Clarion LSP MCP User Guide

Install, register, and diagnose the server that lets an AI assistant read a Clarion solution with the IDE closed.

Applies to version 0.1.0 · Windows workstations with Clarion 11.1 or 12 and the Clarion Assistant addin

0.1.0›User Guides›Clarion LSP MCP

At a glance

Purpose

Lets AI coding assistants (Claude Code, Codex, and any other MCP host) read a Clarion solution through the Clarion Assistant language server while the Clarion IDE is closed: go to definition, find references, hover, symbols, diagnostics, and rename proposals.

Audience

Clarion developers who want their AI assistant to understand a solution, and the support staff who install the server on a workstation, register it with the AI tool, and diagnose it when the tool cannot see the solution.

Prerequisites

Windows 10 or 11. Node.js 20 or newer. A Clarion install (11.1 or 12) that already has the Clarion Assistant IDE addin, which supplies the language server. The AI tool the developer uses must support stdio MCP servers.

Overview

The Clarion Assistant IDE addin ships a full Clarion language server inside the Clarion install folder, but only the running IDE could use it. Clarion LSP MCP is a small program, published on npm as clarion-lsp-mcp, that starts that same language server on its own, points it at a solution, and exposes twelve tools to whatever AI assistant is registered to use it. Nothing is copied or redistributed: the server runs from the existing Clarion install.

When the developer's AI tool starts, it launches clarion-lsp-mcp as a background process. Nothing else happens until the assistant calls open_solution. At that point the program finds the Clarion install, starts the language server from it, tells the server which .sln to index, and waits up to 30 seconds for the server to report ready. After that, every question the assistant asks (where is this procedure defined, does this file have errors) is forwarded to the server and the answer is returned as plain file paths and line numbers.

Note This guide covers installing, registering, and diagnosing the server. It does not cover the Clarion IDE, the Clarion Assistant addin itself, or the AI tools' own installation. The server is read-only: it never edits source files, project files, or .app files, and it never builds or generates code. The one tool that proposes changes, lsp_rename, returns a list of edits for the developer to review and never applies them.

Configuration

There is no configuration file. Behaviour is set by one optional environment variable, by how the server is registered in the AI tool, and by the arguments the assistant passes when it opens a solution.

SettingValueWhereNotes
CLARION_ROOTClarion install folder, e.g. C:\Clarion12User or system environment variableOptional. When unset, the server scans C:\Clarion* for installs that contain bin\Clarion.exe and the Clarion Assistant addin's lsp-server folder, and picks the highest version. Set it when Clarion is on another drive or the developer has several installs and needs a specific one.
Host registrationcmd /c npx -y clarion-lsp-mcpThe AI tool's MCP configuration (see Procedures)The cmd /c prefix is required on Windows because npx is a batch file and some hosts cannot launch it directly. The -y lets npx download the package the first time without a prompt.
solution_pathAbsolute path to a .slnArgument to the open_solution toolOptional. When omitted, the server uses the single .sln in the working directory the AI tool started in. Several .sln files there produce an error that lists the candidates; none produces an error asking for a path.
configurationDebug (default) or ReleaseArgument to open_solutionPassed to the language server as its build configuration. Use the one the developer builds with.
clarion_rootClarion install folderArgument to open_solutionOptional per-call override of CLARION_ROOT. Rarely needed.
Redirection fileA .red beside the .sln, otherwise the first .red in <ClarionRoot>\binChosen automaticallyNot configurable in 0.1.0. The chosen file is reported by get_solution_info as redirectionFile.
Node.js20 or newer on PATHWorkstationOnly needed to run the MCP program itself. The language server uses the node.exe that ships inside the Clarion Assistant addin folder.
Caution If CLARION_ROOT points at a Clarion install that does not have the Clarion Assistant addin, every open_solution call fails with a message naming the folder it expected (accessory\addins\ClarionAssistant\lsp-server). Either install the addin into that Clarion, or unset the variable so auto-detection can find an install that has it.

Procedures

Before publishing The npx commands below only work once clarion-lsp-mcp is published to npm. Until then, clone the repository, run npm install and npm run build, and register node <path>\clarion-lsp-mcp\dist\index.js instead. Registering the npx form early makes the host report CONNECTION_CLOSED because there is nothing to download.

Install and register with Claude Code

  1. Confirm Node.js 20 or newer: open a command prompt and run node --version. If it is missing or older, install the current LTS from nodejs.org and reopen the prompt.
  2. Confirm the language server is present: check that C:\Clarion12\accessory\addins\ClarionAssistant\lsp-server\node.exe exists (substitute the developer's Clarion folder). If it does not, the Clarion Assistant addin is not installed; install it before continuing.
  3. Register the server once, from any folder: 
    claude mcp add clarion-lsp -- cmd /c npx -y clarion-lsp-mcp
  4. Start Claude Code inside the folder that holds the developer's .sln and ask it to run diagnostics on the solution, or run the /lsp-diagnostics skill if the clarion-assistant plugin is installed.
  5. Confirm the first run downloaded the package: the first open_solution can take a minute while npx fetches it. Later starts are immediate.
Tip If the developer's PC has no internet access or npx is blocked by policy, install the package globally on a connected machine with npm install -g clarion-lsp-mcp, copy the resulting folder, and register the command as node <path>\clarion-lsp-mcp\dist\index.js instead of npx.

Register with Codex CLI

  1. Open %USERPROFILE%\.codex\config.toml in a text editor. Create it if it does not exist.
  2. Add this block and save: 
    [mcp_servers.clarion-lsp]
command = "cmd"
args = ["/c", "npx", "-y", "clarion-lsp-mcp"]
  3. Restart Codex. The tools appear under the clarion-lsp server name.

Register with any other MCP host

  1. Find the host's MCP servers configuration file (most use a JSON file with an mcpServers object).
  2. Add this entry: 
    { "mcpServers": { "clarion-lsp": { "command": "cmd", "args": ["/c", "npx", "-y", "clarion-lsp-mcp"] } } }
  3. Restart the host and confirm a tool named open_solution is listed.

Verify the server works on a workstation

  1. Close the Clarion IDE, so there is no doubt the answers come from this server.
  2. In the AI tool, inside the solution folder, ask the assistant to open the solution. It calls open_solution. The reply must show ready: true, the Clarion root it found, and the Clarion version.
  3. Ask for the list of source files. The assistant calls get_project_source_files; the reply lists every .clw and .inc per project with absolute paths.
  4. Ask whether a specific file has errors. The assistant calls lsp_diagnostics; the reply shows pending: false and a count. To prove the server is really analysing, have the developer add an unterminated CASE block to a scratch copy and ask again: the count must become at least one.
  5. Ask for the status. The assistant calls lsp_debug_status; running: true with a numeric pid confirms the language server process is alive.
Success open_solution returned ready: true, get_project_source_files listed the expected files, and lsp_diagnostics answered with pending: false. The workstation is set up correctly.

Update or remove

  1. Update: nothing to do when registered through npx -y; npx checks for the latest published version at each start. To pin a version, register npx -y clarion-lsp-mcp@0.1.0 instead.
  2. Remove from Claude Code: claude mcp remove clarion-lsp. For other hosts, delete the entry from their configuration file.
  3. The Clarion install and the addin are untouched by install or removal. No files are written anywhere except npm's cache.

Tool reference

These are the tool names the assistant uses. Support staff do not call them directly, but they appear in the assistant's transcript and in error reports. Line and character numbers are zero-based. All file paths are absolute Windows paths.

ToolWhat it doesHealthy reply looks like
open_solutionStarts the language server and indexes a solution. Must be called first.ready: true, plus solution path, Clarion root, version, and redirection file.
lsp_startSame as open_solution with no arguments. Kept for compatibility with the clarion-assistant plugin skills.Same as above.
get_solution_infoReports the open solution without touching the server.Solution path and ready flag, or solution: null if nothing is open.
get_project_source_filesLists .clw and .inc files per project.One entry per project with a files list; an unresolved list that is empty.
lsp_definition, lsp_references, lsp_hoverAnswers a question about the symbol at a file position.A list of file path, line, character; or hover text.
lsp_document_symbols, lsp_find_symbolLists symbols in one file, or searches by name across the solution.Names with kinds and positions.
lsp_diagnosticsErrors and warnings for one file, re-reading it from disk first so recent edits count.pending: false with a count. pending: true means no answer within 3 seconds of a changed file, or nothing cached yet for an unchanged one; treat it as unknown, not clean.
lsp_renameProposes a rename. Never writes to disk.An edits list, or an error saying the symbol cannot be renamed there.
lsp_debug_statusHealth check.running: true, a pid, counts of notifications and open documents, and the last lines the server wrote to its error output.

Troubleshooting

SymptomLikely causeFix
The AI tool does not list any clarion-lsp tools, or reports CONNECTION_CLOSED.The registration command could not start. Causes in order of likelihood: the npx form was registered before the package was published; npx launched without cmd /c; Node.js missing from PATH.Re-register with the exact command in Procedures. Run cmd /c npx -y clarion-lsp-mcp by hand in a command prompt: it should sit silently waiting for input (press Ctrl+C to stop). Any error it prints is the cause.
open_solution error: "No Clarion install with the Clarion Assistant addin found under C:\Clarion*".Clarion is on another drive or folder name, or the addin is not installed.Set CLARION_ROOT to the install folder and restart the AI tool. If the addin's lsp-server folder is missing from that install, install the Clarion Assistant addin.
open_solution error: "No .sln file in ..." or "Several .sln files in ...".The AI tool started in a folder without exactly one solution.Have the developer ask the assistant to open the solution by full path, or start the AI tool inside the solution folder.
open_solution returns ready: false with a stderrTail.The language server started but did not finish indexing within 30 seconds. On large solutions this is normal; the server keeps indexing and later calls work. If stderrTail mentions a rejected payload or missing paths, the redirection file is wrong.Wait a minute and try a tool such as lsp_document_symbols. If it works, no action. If stderrTail shows path errors, check that the .red beside the .sln is the one the IDE uses.
Every tool replies "No solution open. Call open_solution first."The assistant skipped open_solution, or the AI tool was restarted (state does not persist across restarts).Ask the assistant to open the solution again.
lsp_diagnostics keeps returning pending: true.The server has not published diagnostics for that file within 3 seconds, or the file has not changed since the last answer and nothing is cached. Common right after opening a big solution.Retry once. If it persists, run lsp_debug_status: running: false means the server died (see next row); running: true with a rising notification count means it is still indexing.
lsp_debug_status shows running: false.The language server process exited or crashed.No action needed for one crash: the next tool call restarts the server and re-indexes before asking, and a call interrupted by a crash is retried once. If the reply says "failed again after restart", read the included stderrTail and report it with the solution name. Check that antivirus is not blocking node.exe inside the addin folder.
Results point at the wrong file, or a symbol is "not found" that clearly exists.The solution was indexed with the wrong configuration or redirection file, so include paths differ from what the IDE uses.Have the assistant call open_solution with configuration: "Release" if the developer builds Release. Compare redirectionFile from get_solution_info with the .red the IDE shows in project properties.
Critical Do not delete or "clean up" the accessory\addins\ClarionAssistant\lsp-server folder or its node_modules to free space: that is the language server itself, and both the IDE addin and this MCP stop working. Recovery is reinstalling the Clarion Assistant addin. Likewise, lsp_rename results are proposals only; if an assistant applies a rename across many files, the developer's source control is the only undo. Never apply a rename without reviewing the edit list.
