### TC-11 Workspace symbol search by name: FAIL (2026-09-18 03:21)

Sent to worker (first four letters of `reg:WIN:ShowExits`):

```json

```
Solution open on server pid 12792 throughout (the same instance that answered TC-08 to TC-10). The worker then retried once on its own: 1692 rows, `reg:WIN:ShowExits` present (regWindow.clw line 156 and reg_WIN_ShowExits.clw line 20, each listed twice with a case-different file name), `reg:ITEM:GetAction` present; but 190 rows had `name` values of 100,000 to 145,000 characters and the reply was 11.3 MB.

**Root cause (orchestrator investigation, scratch probes against the install):**

1. Server, `ClarionDocumentSymbolProvider` FILE support: KEY/INDEX children are found by upper-casing every token inside the FILE and comparing to `KEY`. In `regItem.clw` line 496 the key is labelled `Key` (`Key  KEY(RSNP:Tx_No,RSNP:SeqNum),DUP,...`); the label token matches, `extractParenContent(tokens, j+2)` then starts on the `(` with depth already 1 and never returns to 0, so the symbol name is the rest of the file. Reproduced in-process: 21 names over 1000 characters in that one file, three of about 140,000.
2. Server, `WorkspaceSymbolProvider`: `seenUris` holds raw URI strings; cached URIs (`REG_WIN_SHOWEXITS.CLW`, from MEMBER/INCLUDE spelling) and project URIs (`reg_WIN_ShowExits.clw`) differ in case, so the file is scanned and reported twice.
3. MCP, `src/lsp.ts` `request()`: the timeout timer was never cleared when the request settled. Harmless in the long-lived server but it kept every probe process alive for the full budget, which is why two scratch probes looked hung for 9 to 10 minutes.
4. Cold cost: a raw `workspace/symbol` on the unpatched install measured 63 s and 67 s cold, 2 to 4 s warm; in-process tokenising of all 1720 .clw/.inc files is 60 s of the 65 s total. The worker's 120 s timeout happened with four Claude sessions busy on the laptop.

**Fix:** `docs/server-patches/workspace-symbols.cjs` (applied to the install; `.patch`, `verify-workspace-symbols.mjs`, README section and `ISSUE-workspace-symbols.md` draft added, not filed upstream). `src/lsp.ts`: timer cleared on settle, `SLOW_REQUEST_TIMEOUT_MS` 120 s -> 300 s. Unit tests 32/32 pass, dist rebuilt.

Root cause: `ClarionDocumentSymbolProvider` classifies shorthand prototypes as `MapProcedure` with `label = value` (no prefix, `ShowExits`) and writes into the shared cached tokens; the workspace scan runs it on every file. The include-prototypes classifier (patch 1) skipped tokens that already had a sub-type, so the include's prototype kept the prefix-less label and the MAP lookup for `reg:WIN:ShowExits` missed. Fix: edit 4 of `docs/server-patches/include-prototypes.cjs`, re-label regardless of an existing sub-type (skip only structure members); the script is now idempotent per edit so it upgrades the install in place (fresh-apply and upgrade paths verified to produce identical files). `include-prototypes.patch` regenerated; addendum drafted in `ISSUE.md` (not posted).
